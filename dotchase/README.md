# Dot Chase：VMで動くパックマン風ゲーム

固定迷路の餌を集め、追跡する敵を避ける小規模なゲームです。移動・餌・得点・敵の追跡・当たり判定・勝敗は、アセンブリから生成したバイトコードを自作VMで実行します。C側は端末の入出力とフレーム待機を担当します。既存ROMや画像・音声は使用しません。

プロジェクト直下で `make run`、`4: Dot Chase` を選びます。単独起動は次のとおりです。

```sh
make -C vm
make -C dotchase
vm/build/handmade-vm --game dotchase/build/dotchase.bin
```

`@` が自分、`G` が敵、`.` が餌、`#` が壁です。16列×11行の迷路で89個の餌をすべて集めるとクリアし、敵と重なるとゲームオーバーです。プレイヤーが敵のマスへ移動した場合は、そのマスの餌を取る前に終了します。敵が移動して自分に到達した場合も、クリアよりゲームオーバーを優先します。パワーアップ・残機・ステージ追加はありません。

| キー | 操作 |
| --- | --- |
| W/A/S/D | 上・左・下・右へ1マス移動。大文字も使用可能 |
| X | 移動入力をキャンセル。敵は動き続ける |
| R | 餌・得点・敵・自分の位置を最初から |
| Q | 共通メニューへ戻る。単独起動では終了 |
| Enter | クリア・ゲームオーバー画面から戻る |

キー入力にEnterは不要です。20ms周期で入力を確認し、入力があるときだけ1マス進みます。入力がなければその場に止まり、最後の方向への自動移動は行いません。移動は最大160ms間隔に抑え、連打や長押しの余った入力を後へ溜めないため、入力を止めた後に走り続けません。移動待ち時間中の入力は次の移動に持ち越しません。長押しのリピート開始・間隔はOSのキーボード設定に従います。敵は24更新ごと（通常約480ms）に現在の自分への最短経路を1マス進みます。1更新で最大32バイトの入力を確認し、その更新では最後の移動入力を採用します。処理が遅れた場合に、遅れた分を連続更新することはありません。

表示は32列×18行のASCIIフレームです。64桁×24行以上のANSI対応端末では同じ位置を描き直します。終了・Ctrl-C・SIGTERM・SIGHUP・VM実行時エラーで端末設定とカーソルを復元します。パイプの入力終端でも終了します。開発者のZero 2 Wでは、実機反映・自動検証に加え、10インチ画面での移動・入力なしの停止・R再開・結果画面Enter・Q復帰・Ctrl+C中断・メニュー自動再表示を確認済みです。公開用のpi設定での実機適用は未実施です。

## VMへの追加

新しいサービスは `--game` のときだけ有効です。既存の命令形式とSYSCALL 0〜3は維持し、`--bot` では追加番号を従来どおり未実装エラーにします。ゲームは常駐する1つのVM内で進行します。

ゲーム用ABIの正式仕様は下表のとおりです。SYSCALL番号4〜6、32×18、EOF＝256、待機1〜1000msを使用します。

| 命令 | 入力・出力 |
| --- | --- |
| `SYSCALL 4` | R0が指す連続576バイトを32×18のフレームとして表示。全バイトがASCII 32〜126であることとメモリ範囲を表示前に検査。レジスタは保持 |
| `SYSCALL 5` | 入力待ちをせず1バイト取得してR0へ返す。0＝入力なし、1〜255＝入力バイト、256＝EOF。ほかのレジスタは保持。NUL入力も0として扱う |
| `SYSCALL 6` | R0の1〜1000msをフレーム間隔として、単調増加時計で待機。ゲーム処理時間を含めて次の更新まで待ち、遅延を蓄積しない。レジスタは保持 |

`vm/notes/game_io.c`・`.h` が端末処理を担当し、`vm.c` がメモリ検査とモードの区別を行います。単に命令を回し続けるプログラムもCtrl-Cで中断できます。

## 端末終了時の入力と信号

ゲームの終了時に、未処理の入力は捨てず、呼出元の共通メニューへ引き継ぐ仕様です。これは端末とパイプ入力の両方に適用します。Qの直後に長押しのリピートや連打の残りがあると、メニューの次の入力行に混ざって無効入力になることがあります。その場合はEnterで入力行を確定し、表示に従って選び直してください。ゲーム中にエコー無効の状態で入力された残りの文字は、メニュー画面に表示されません。小文字のqが1文字だけ残っている場合は、Enterで共通メニューが終了します。Zeroの自動起動環境では、その後systemdがメニューを再表示します。

端末設定とカーソルの復元を扱うのは、通常終了・VM実行時エラー・SIGINT（Ctrl+C）・SIGTERM・SIGHUPです。SIGQUIT（Ctrl+\）・SIGTSTP（Ctrl+Z）は復元の保証対象外です。ゲームを中断してメニューへ戻る操作はQまたはCtrl+Cを使います。

## 時間検証の範囲

20ms・160ms・約480msは、設定した待機間隔と更新回数から求めた値です。ゲームのテストでは、移動待ち8更新と敵の24更新をフレーム数で確認しています。VM入出力の待機テストは、範囲外の値の拒否と短い待機が入ることを確認する簡単な検査で、実時間の精度や遅れからの回復を保証する検査ではありません。

実装は単調増加時計を使い、遅れた期限を現在時刻へ合わせます。2026-11-27、開発者のZeroで実際の `game_io.c` を一時測定プログラムへリンクして測定しました。20ms指定300回の平均は20.0827ms、最小20.0660ms、最大20.1170msでした。約200msの遅延を3回挿入すると、期限超過直後の待機は0.002865〜0.002969msで戻り、その後各12回は20.0790〜20.1086msで、遅れた更新を連続実行する挙動は観測されませんでした。

これは待機関数を測定した1回の結果で、配置済みVMバイナリやゲーム全体の周期・画面表示時間を測定したものではありません。精度の許容誤差は未定義で、この結果や入力応答のMac・Zero各1回の計測値を一般的な精度・応答保証には使いません。

## ソースと検証

`generate_game.py` は `game.asm` と、固定迷路用の最短経路表を生成します。Pythonは開発時だけ使い、プレイ中は起動しません。敵の現在地とプレイヤーの現在地を使って、VMが表から次の1歩を選びます。経路の長さが同じなら上・左・下・右の順です。動的なゲーム状態とフレームはVMメモリに保持します。

```sh
python3 -B dotchase/generate_game.py
make -C dotchase
python3 -B vm/test_game_io.py
make -C dotchase test
```

VM入出力の範囲検査・モード分離・時間待機・端末復元と、実際のバイトコードを使う移動・餌・追跡・勝敗・再開・メニュー復帰を検証します。勝敗の境界は、同じ生成処理で作った小さい迷路でも確認します。
