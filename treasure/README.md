# 宝取り競争

自作VM上のボットが宝を集めるターン制の対戦ゲームです。共通メニューの `2: Treasure` から、専用の付属ボットを選んで起動できます。共通メニューの操作は [console/README.md](../console/README.md) を参照してください。以下のコマンドによる単独起動も可能です。

## ルール

- 16×16マス、2〜4体、200ターン。座標は左上が `(0,0)`、右下が `(15,15)`。
- 開始位置はID順に `(0,0)`、`(15,15)`、`(15,0)`、`(0,15)`。
- 宝はx・yがそれぞれ `2,4,6,9,11,13` の組み合わせになる36マスに固定配置する。中央の `(6,6)`、`(9,6)`、`(6,9)`、`(9,9)` は5点、残り32個は1点。合計52点。
- 行動は `W`（上）、`A`（左）、`S`（下）、`D`（右）、`X`（待機）。盤面外への移動はその場に留まる。
- 全員がターン開始時の同じ状態を見て判断する。全員の移動後、そのマスにボットが1体だけいれば宝を取得し、得点を加算して宝を取り除く。待機でも取得できる。
- ボット同士は重なれる。複数体がいるマスの宝は残り、後のターンで1体だけになれば取得できる。位置の交換は可能。
- 宝の再配置はしない。宝をすべて取得しても200ターンまで続け、最高得点のボットが勝つ。最高得点が同じなら引き分け。
- 毎ターン、ボットごとにVMを起動し直す。1応答の期限は100ms。タイムアウト・不正出力・VMエラーはそのターンの待機とする。ホストによるプロセス生成・VM起動の失敗は試合を中断する。

## macOSでビルド・対戦

取得した `paintbot-vm/` の直下で実行します。ゲーム自体は開発者のZero 2 Wでビルド・対戦・10インチ画面での操作を確認済みです。公開用の実機配置・運用例は [console/DEVICE.md](../console/DEVICE.md) を参照してください。

```sh
make -C vm
make -C treasure
treasure/build/treasure-host --watch vm/build/handmade-vm treasure/build/seeker-h.bin treasure/build/seeker-v.bin
```

2〜4個のボットを引数で渡します。登録操作は不要です。同じボットの複数参加も可能です。`--watch` はANSI端末の観戦表示（64桁×24行以上、1ターン最低200ms）、`--no-watch` は最終結果だけを表示します。省略時はANSI対応端末なら観戦、それ以外は最終結果です。

`seeker-h`・`seeker-v` は、固定配置のうち残っている近い宝を目指すボットです。距離が同じ場合の優先順と、縦横どちらから近づくかが異なります。他のボットの行動予測は行いません。

他のボットと重なった場合は、その場にいる最小IDのボットが待機し、残りは右へ1マス（右端なら左へ1マス）退避します。全員が同時に動いて競合を繰り返すことを避け、宝の上なら待機した1体が取得できるようにします。通常の探索では自分の現在位置を候補から除外し、候補の宝が残っていなければ待機します。`right` と `wait` は動作確認用です。

ボットの実行は既存VMの命令だけを使います。Pythonはソース生成とテストにのみ使用します。

```sh
make -C treasure test
```

## ボット入出力：TREASURE1

入力はASCII・LF改行。先頭は識別行 `TREASURE1`、続いて16文字×16行の盤面です。`.` は空き、`1`・`5` は宝の点数です。ボットの位置を盤面へ上書きしません。

続いて `自分のID 残りターン 参加体数` の1行（例：`1 200 2`）、ID順の `ID X Y 得点` の行（例：`1 00 00 000`）を参加体数分渡します。残りターンと得点は3桁、座標は2桁。試合開始時の残りターンは200、最終行動時は001です。

出力は行動1文字とLFのちょうど2バイトで、正常終了する必要があります。paintbotと入力の識別行・盤面の意味・位置レコードが異なります。ボットを取り違えないでください。

観戦画面では `o` が1点の宝、`$` が5点の宝、数字がボット、`*` が3体以上の重なりです。背景色は宝の有無を表し、ボットが重なっていても残った宝を確認できます。
